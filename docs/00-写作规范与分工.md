## 1 交付目标

1. 交付物：《维修百事通·提示词工程规范》单文件，Markdown 版 + Word 版。
2. 字数口径：Word 字数（中文字符 + 西文单词）目标 20,000–22,000；中文字符数不少于 19,000。
3. 内容：包含可直接投产的提示词资产——全局系统提示词 1 套、场景提示词 7 套、检索/安全/修复/评估提示词各 1 套、四类结构化输出 Schema、评估方案、端到端示例库。
4. 文风：工程规范体，不用营销话术与 AI 腔。

## 2 产品设定

维修百事通是面向企业设备维护场景的故障诊断知识助手，四类核心能力：

1. 故障问答：基于设备台账、维修手册、SOP、历史工单做 RAG 问答，给出故障判断、依据、处置与风险。
2. 排查引导：用决策树逐步提问，引导现场人员定位故障，每轮只问一个关键问题。
3. 点检清单：按设备类别与点检频次（日/周/月/年）生成可执行点检表。
4. 工单流转：从自然语言报修中抽取工单字段、判定等级、建议派单、跟踪回填与闭环，沉淀知识。

形态：Web 与企业微信/钉钉入口；基座模型 DeepSeek-V3.1（可替换同级别模型）；知识库为企业自有维护知识；可调用设备台账、知识检索、历史工单、转人工等工具。
用户：操作工、维修工、设备管理员、班组长、安全员。

### 3.3 编号约定

- 知识条目：KB-<领域>-<4位>，例 KB-CNC-0042、KB-AIR-0011、KB-PWR-0007。
- 工单：WO-YYYYMMDD-NNNN，例 WO-20261026-0012。
- 点检项：CHK-<类别>-<频次>-<3位>，频次取 D/W/M/Y，例 CHK-CNC-D-012。
- 提示词资产：WXBST-<类型>-<3位>。类型：SYS 系统、RTR 路由、QA 问答、TRG 引导、CHK 点检、WO 工单、EXT 抽取、RAG 检索、SEC 安全、FIX 修复、EVL 评估。

## 4 写作风格与格式

1. 简体中文，工程规范体：短句、结论先行；规则用“必须/不得/应/建议”。
2. 禁止 AI 腔与营销话术：如“综上所述”“总而言之”“赋能”“闭环生态”“在数字化时代”“极大提升”。
3. 每段必须承载信息：规则、参数、判据、示例或理由；不写无信息量的铺垫。
4. 标题层级：章用一级标题，节用二级标题；原则上不用三级标题，全篇不超过 10 处。
5. 表格用于对照，最多 6 列；提示词统一放进代码块，语言标注 text；JSON 用 json 代码块。
6. 交叉引用写“见 3.3 节”“见 WXBST-QA-001”“见附录 12.1”。
7. 每个提示词块前后给出：编号、版本 v1.0、适用模型、输入变量、输出约定；块后用 2–4 句设计说明，说明为什么这样写、如何防错。

## 5 提示词撰写规范

1. 变量统一 {{snake_case}}，如 {{equipment_model}}、{{history_orders}}；变量缺失时按“未知”处理，不得编造。
2. 提示词结构统一：## 角色 / ## 任务 / ## 输入 / ## 工作流程 / ## 约束 / ## 输出格式 / ## 示例，可按需裁剪，但角色、约束、输出格式必须保留。
3. 约束必须可判定：写“追问不超过 3 个问题”，不写“尽量简洁”。
4. 危险场景必须给出拦截动作：停机、断电、挂牌上锁、撤离、转人工。
5. 输出示例必须完整可读；JSON 字段用小驼峰，枚举值用英文大写（HIGH/MEDIUM/LOW），时间用 ISO 8601。
6. 引用知识必须带来源标记，如 [KB-CNC-0042]；无证据时必须明说“知识库未检索到”。

## 8 质量红线（提交前逐条自检）

1. 标题与编号符合第 7 节，逐字一致；不得新增、合并、调换章节。
2. 文件内不写 YAML 头、不写文档大标题、不写目录；第一行就是本章一级标题。
3. 术语、设备编码、工单号、提示词编号与第 3 节完全一致；示例数值符合 3.2。
4. 每个提示词可直接复制使用：含角色、任务、约束、输出格式；变量有定义（与 12.1 变量字典不冲突）。
5. 安全内容写清“触发条件 → 必须动作”，不含含糊表述。
6. 不留占位符（“待补充”“TODO”“……”单独成段）、不出现“本段略”。
7. JSON 代码块可被解析；枚举值、字段名前后一致。
8. 全篇中文标点；英文术语首次出现给中文解释。

## 9 工作方式

1. 只写任务指定的文件；不得修改本文件、其他草稿或项目其他文件；不得调用 spawn_teammate 或 subagent。
2. 先读本文件，再写；写完后运行字数统计自检。
3. 在看板上 claim 自己的任务，完成后 complete；再向 lead 发送完成报告。
4. 单文件较长时，可先写前半，用 edit 将 <!--PART2--> 占位符替换为后半；交付时不得残留占位符。
